# Writing the fields

One story across every field: the name says what the app is, the next line says why it's better, the description proves it, and the screenshots show it.

## Name / title (both stores, 30)

1. Pattern: `Brand: Head Keyword Phrase` or `Brand - Phrase`. Lead with the phrase only if the brand is unknown and short on space.
2. One keyword theme. Put further phrases in the subtitle or short description.
3. No promotional, ranking or price words (`policy.md`).

- Apple: simple, memorable, hints at what the app does; avoid generic names. [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19
- Google: unique, avoid common terms and misspellings of general terms; long titles get truncated on some devices. [official](https://support.google.com/googleplay/android-developer/answer/4448378) · 2026-11-19
- `Brand: Keyword` pattern; focus beats stuffing. [practitioner](https://appfigures.com/resources/guides/app-name-optimization) · 2026-11-19

## iOS subtitle (30)

1. The value or the main use case, and new keywords only, with none repeated from the name.
2. Front-load the first ~26 characters.
3. No unverifiable claims ("world's best").

- Use the subtitle "to explain the value of your app in greater detail". [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19

## Play short description (80)

1. The biggest benefit in plain language, with 1–2 target terms used naturally.
2. Must not repeat the opening of the full description.
3. No price, rank or CTA words.

- Convey the message, the biggest benefits, simple language; no pricing or ranking. [official](https://support.google.com/googleplay/android-developer/answer/13393723) · 2026-11-19

## Description (4000)

Shape for both stores:

1. **Positioning sentence:** "[App] is a [type] that helps [audience] [goal]." It is readable without tapping More, and it is what AI surfaces quote.
2. A 1–2 sentence value paragraph.
3. Feature bullets, most important first, one outcome each, using the same feature names as the website.
4. Proof the developer can verify (attributed quotes only on Play).
5. Subscription terms if relevant.

On iOS the description isn't ranked, so write it purely for conversion. On Play it is ranked: keywords go in the first three sentences and the bullets, at 3–5 mentions of the primary term.

- Positioning opener "[App] is a [type] that helps [audience] [goal] by [capabilities]"; avoid "all-in-one" and "ultimate". [practitioner](https://www.apptweak.com/en/aso-blog/optimize-app-store-listing-for-ai-search) · 2026-11-19
- Paragraph, then feature bullets, then social proof; Play keywords at sentence starts and in bullets. [practitioner](https://www.apptweak.com/en/aso-blog/app-store-description-best-practices) · 2026-11-19
- Don't add unnecessary keywords to the iOS description. [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19

## Promotional text (iOS, 170)

News, a season or an event. You can swap it without a release, and it has no ranking effect.

- Promotional text is for news and limited-time events. [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19

## What's New / release notes

1. Changes in order of importance, specific, ending with a call to action.
2. iOS: generic notes only for bug-fix-only releases (2.3.12).

- List changes by importance and add a call to action. [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19

## Screenshot captions (input to the screenshot brief)

1. One benefit per screenshot, in active voice, phrased the way a user would phrase it ("Track every workout", not "Workout tracker app").
2. Slides 1–3 carry the pitch, because search shows only those.
3. Make captions keyword-aware but **never count on them for keyword coverage**. Indexing of caption text is unproven.
4. Play screenshot text follows the preview-asset rules: no "Best", "#1", "Free", or CTAs.

- First 1–3 screenshots appear in search when there is no preview video. [official](https://developer.apple.com/app-store/product-page/) · 2026-11-19
- Benefit-driven captions; most compelling features in the first three. [practitioner](https://www.apptweak.com/en/aso-blog/how-to-optimize-your-app-screenshots) · 2026-11-19
- Make captions readable and keyword-aware, and never rely on them for coverage. [practitioner](https://phiture.com/blog/aso-trends-in-2026/) [data](https://consultmyapp.squarespace.com/blog/-is-apple-now-indexing-screenshot-titles-on-the-app-store) · 2026-11-19
- Creative should keep the promise of the top keywords in the title and subtitle. [practitioner](https://www.moburst.com/blog/mobile-app-keyword-research-for-smarter-aso-growth/) · 2026-11-19
